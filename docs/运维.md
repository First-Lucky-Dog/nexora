# 运维手册

## 生产发布（aidraw365.com）

> Claude Code 用户可直接使用项目 skill `deploying-production`，其内容与本节保持同步。

### 环境概况

- **主机**：海外 VPS（Ubuntu 22.04，4C/4G/80G，~7G swap）。SSH 登录信息（IP/端口/用户）**不入库**，见本地密码管理器/部署记忆
- **部署目录**：`/data/new-api`（Docker Compose），代码在 `/data/new-api/data/nexora`
- **容器**：`new-api` / `new-api-postgres`（PG15）/ `new-api-redis`
- **反代**：Cloudflare → Caddy（`/etc/caddy/Caddyfile`）→ `127.0.0.1:3000`
- **镜像命名**：`nexora-new-api:<git短commit>`；`web/*/dist` 不在仓库，由 docker build 内部构建
- **代码来源**：`origin` = First-Lucky-Dog/nexora（线上只拉这个）；`upstream` = QuantumNous/new-api（勿在服务器上拉）

### 发布步骤

**本地：**

1. 确认改动已合并到 `main`，更新 `VERSION` 文件，提交
2. `git push origin main` —— **禁止打 tag**（tag 会触发上游 CI 向 calciumion DockerHub 推镜像）
3. 记下新的短 commit（`git rev-parse --short HEAD`），作为镜像 tag

**服务器（每步确认成功再进行下一步）：**

```bash
# 1. 备份（缺一不可）
cd /data/new-api
TS=$(date +%Y%m%d-%H%M%S)
mkdir -p backups/release-before-update-$TS && cd backups/release-before-update-$TS
cp /data/new-api/.env .env.bak
cp /data/new-api/docker-compose.yml docker-compose.yml.bak
sudo cp /etc/caddy/Caddyfile Caddyfile.bak
grep NEW_API_IMAGE /data/new-api/.env > current-image.txt
(set -a; . /data/new-api/.env; set +a; \
 cd /data/new-api && docker compose exec -T postgres pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB") | gzip > postgres-full.sql.gz
ls -lah   # 确认 .env.bak（隐藏文件）和 postgres-full.sql.gz 大小正常

# 2. 拉代码 + 构建（4G 内存靠 swap，5-15 分钟）
cd /data/new-api/data/nexora
git pull --ff-only origin main
git log --oneline -1          # 确认是预期 commit
docker build -t nexora-new-api:<新短commit> .

# 3. 切换镜像并重建
sed -i 's|^NEW_API_IMAGE=.*|NEW_API_IMAGE=nexora-new-api:<新短commit>|' /data/new-api/.env
cd /data/new-api && docker compose up -d --force-recreate new-api

# 4. 验证
docker compose ps new-api                                          # IMAGE 应为新 tag，healthy
docker compose logs new-api | grep -icE 'error|fatal|panic'        # 计数应为 0（此时 grep 退出码非零属正常）
curl -s 127.0.0.1:3000/api/status | grep -o '"version":"[^"]*"'    # 应为新版本号
```

浏览器验收：首页品牌 → 登录 → 管理后台各页 → 渠道页 → 测试对话计费。

### 回滚

```bash
sed -i 's|^NEW_API_IMAGE=.*|NEW_API_IMAGE=<current-image.txt 中的旧 tag>|' /data/new-api/.env
cd /data/new-api && docker compose up -d --force-recreate new-api
# 极端情况恢复数据库：
# gunzip -c backups/release-before-update-<TS>/postgres-full.sql.gz | docker compose exec -T postgres psql -U <用户> <库名>
```

### ⚠️ 已踩过的坑

1. **不要在操作 compose 的 shell 里 `set -a; . .env`**：shell 环境变量优先级高于 .env 文件，导致改 `.env` 切不动镜像。需要读 .env 变量时用子 shell `( set -a; . .env; ... )`。若已污染：`unset NEW_API_IMAGE` 或换新会话。
2. **不要打 git tag**：会触发上游遗留 CI 往外部 DockerHub 推镜像。
3. `SERVER_ADDRESS` 与 `FRONTEND_BASE_URL` 必须一致（曾因不一致导致注册验证/登录跳转/钱包页异常）。
4. `ls -lh` 看不到 `.env.bak`（点开头隐藏文件），确认备份用 `ls -lah`。

## 本地开发常用命令

```bash
# 重新构建后端，保留本地数据
docker compose -f docker-compose.dev.yml up -d --build new-api

# 查看容器状态 / 日志
docker compose -f docker-compose.dev.yml ps
docker compose -f docker-compose.dev.yml logs -f new-api

# 健康检查
curl http://localhost:3000/api/status

# 代码没生效时无缓存重建
docker compose -f docker-compose.dev.yml build --no-cache new-api
docker compose -f docker-compose.dev.yml up -d new-api
```
